# U1 Backend Planning Core — Code Summary

Generated application code lives under `backend/` at the workspace root. This document is the map from
the approved design to the code that implements it.

## Layout

```text
backend/
├── openapi/planning-api.yaml              # checked-in API contract, drift-tested against the routes
├── src/main/java/com/timetable/todo/
│   ├── PlanningApplication.java
│   ├── planning/
│   │   ├── PlanningConfiguration.java     # wires the framework-free service to its adapters
│   │   ├── domain/                        # B-C01, B-C02: no Spring, JPA, servlet or SQL import
│   │   ├── application/                   # B-C03~B-C05: use cases, ports, typed outcomes
│   │   └── adapter/
│   │       ├── in/web/                    # B-C07, B-N02: DTOs, controllers, safe error mapper
│   │       └── out/persistence/           # B-C06: JPA entities, repositories, port adapters
│   ├── platform/                          # B-N01, B-N05, B-N06: filters, security, limits, guards
│   └── resources/
│       ├── application.yml                # loopback, health-only actuator, platform limits
│       ├── application-file.yml           # encrypted file profile, no usable secret
│       ├── db/migration/                  # B-N04: forward-only Flyway schema
│       └── static/docs/                   # self-hosted Swagger UI, no CDN asset
└── src/test/java/                         # B-N07: example, property, architecture, contract tests
```

## Design Decisions Recorded During Generation

Both were ambiguous or absent in the approved design and were resolved with the user (see `audit.md`):

1. **`PATCH` replaces the full content set.** Title, priority and estimate are required; an omitted
   description or due date clears that value. Completion and placement keep their own endpoints. This
   keeps FR-003 validation identical for create and edit and matches the editor form one-to-one.
2. **A changed estimate resizes an existing placement in place.** The start time is preserved and the
   end recalculated. If the longer block overlaps, the request returns `409 SCHEDULE_CONFLICT` with a
   candidate and writes nothing; if it leaves the planning window, it returns `400`. This reuses the
   already-approved FR-007 recovery flow instead of inventing a second one.

A third choice was made for the contract itself: `planning-api.yaml` is authored directly and bound to
the code by `OpenApiContractDriftTest`, rather than generated by a runtime documentation library. That
keeps `/v3/api-docs` and a live spec generator off the attack surface (SECURITY-09) while still making
drift impossible to merge. Swagger UI renders the same file from self-hosted assets.

## Defect Found by Test-First Development

The next-candidate search used the task's stored estimate rather than the length of the proposed
interval. When an edit grew a scheduled task, the server could offer a candidate slot that was too
short for the new estimate. A failing contract test exposed it before the adapter existed; the fix
derives the length from the proposed slot itself.
