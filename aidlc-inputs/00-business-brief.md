# 00. 비즈니스 브리프 — 무엇을 / 왜 만드는가

## 1. 한 문장 정의

개인이 미배치 할 일을 주간 타임테이블에 직접 배치하고 충돌을 해결하며 실행 가능한
주간 계획으로 전환하는 로컬 중심 웹 애플리케이션이다.

## 2. 해결하려는 문제

- 일반 투두 리스트는 해야 할 일의 양은 보여 주지만 실제로 언제 수행할지는 보여 주지 않는다.
- 사용자는 목록과 캘린더를 오가며 시간을 수동으로 대조해 계획한다.
- 이 과정에서 과도한 일정 배치, 시간 충돌, 미처리 할 일 누락이 발생한다.

## 3. 대상 사용자

| 페르소나 | 상황 | 이 제품으로 얻는 것 |
|---|---|---|
| 개인 지식 근로자 | 한 주의 여러 할 일을 실제 가능한 시간에 배치해야 함 | 목록과 주간 시간표를 한 화면에서 조정하고 충돌을 사전에 발견 |

## 4. 핵심 사용자 여정

1. 사용자가 할 일을 만들면 미배치 백로그에 나타난다.
2. 사용자가 할 일을 주간 타임테이블로 끌거나 시간을 입력하면 일정으로 배치된다.
3. 시간이 겹치면 사용자가 기존 일정 유지, 새 일정 이동 또는 취소를 선택한다.
4. 사용자가 할 일을 완료하면 목록과 타임테이블에 즉시 반영된다.
5. 사용자가 주간 보기와 목록 보기를 오가며 전체 계획을 검토한다.

## 5. 성공 기준

- 신규 사용자가 3분 안에 할 일 생성부터 타임테이블 배치와 완료까지 수행할 수 있다.
- 겹치는 일정은 저장 전에 100% 탐지되어 명시적 선택 없이 덮어쓰지 않는다.
- 데스크톱과 모바일 핵심 흐름에 자동화된 E2E 테스트가 존재한다.
- 백엔드와 프론트엔드 모두 합의된 커버리지 기준을 충족한다.
- 데모에서 백로그 생성, 드래그 배치, 충돌 해결, 완료, 주 이동과 목록 전환을 보여 준다.

## 6. 범위

### 이번에 만든다

- 월요일 시작 주간 타임테이블과 이전 주·다음 주·오늘 이동
- 미배치 할 일 백로그
- 할 일 생성, 조회, 수정, 삭제, 완료와 완료 취소
- 우선순위, 예상 소요 시간, 마감일
- 드래그 또는 직접 시간 입력을 통한 일정 배치와 재배치
- 일정 충돌 탐지와 명시적 해결
- 목록 보기, 로딩·빈 상태·오류·성공 피드백
- 데스크톱 및 모바일 반응형 UI와 키보드 접근성
- H2 파일 영속화 및 테스트용 인메모리 프로필
- 프론트엔드·백엔드 테스트, 보안 리뷰, 의존성 취약점 검사

### 이번에 만들지 않는다

- 로그인, 다중 사용자, 팀 협업과 권한
- 담당자 배정, 댓글, 첨부파일, 하위 작업
- 칸반 보드와 반복 일정
- 알림, 외부 캘린더 연동, 모바일 네이티브 앱
- 클라우드 배포와 고가용성 인프라

## 7. 제약 조건

- 기간: 단일 MVP 개발 사이클
- 인원/역할: AI 개발 에이전트와 승인 담당 사용자 1명
- 예산·비용 상한: 로컬에서 무료 오픈소스 의존성만 사용
- 데이터 제약: 개인정보와 인증정보를 저장하지 않으며 로컬 데이터만 처리
- 시간 정책: Asia/Seoul, 월요일 시작, 15분 단위, 기본 08:00~22:00
