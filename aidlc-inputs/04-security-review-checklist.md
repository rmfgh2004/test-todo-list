# 04. 코드 작성 시 보안 리뷰 체크리스트

모든 코드 생성·수정 묶음 직후 이 체크리스트를 수행한다. 적용 가능한 미충족 항목은
차단 결함이다. 결과는 unit별 `security-review.md`에 날짜, 변경 파일, 관련 안정 ID,
판정과 근거를 append한다.

## A. 입력 및 출력

- [ ] 모든 API·폼 입력에 타입, 길이, 범위, 형식 allowlist가 있다. (SECURITY-05)
- [ ] 제목·설명 등 사용자 문자열은 HTML로 직접 삽입하지 않는다.
- [ ] SQL, 명령, 경로를 사용자 문자열 결합으로 만들지 않는다.
- [ ] 오류 응답과 UI 오류는 내부 경로, 스택, SQL, 프레임워크 버전을 노출하지 않는다.
- [ ] 요청 본문 크기와 컬렉션 최대 개수를 제한한다.

## B. 접근 및 경계

- [ ] 모든 공개 엔드포인트가 의도적으로 공개되었는지 명시한다. (SECURITY-08)
- [ ] 서버는 기본적으로 loopback에 바인딩되고 CORS origin은 allowlist다.
- [ ] 상태 변경은 프론트 UI가 아니라 백엔드 도메인 규칙으로 다시 검증한다.
- [ ] API 속도 제한과 실패 시 차단 동작을 우회할 수 없다. (SECURITY-11, SECURITY-15)

## C. 데이터 보호

- [ ] 비밀값, DB 키, `.env`, H2 파일이 Git 추적 대상이 아니다. (SECURITY-01, SECURITY-12)
- [ ] 개발 H2 파일은 암호화되고 키는 환경 변수로 주입된다.
- [ ] 로그에 비밀값, 전체 사용자 입력, 개인정보가 포함되지 않는다. (SECURITY-03)
- [ ] 데이터 변경은 트랜잭션으로 처리하고 실패 시 전체 롤백된다.
- [ ] 중요한 변경에는 시각, 동작, 리소스 ID와 변경 요약 감사 기록이 남는다. (SECURITY-13)

## D. 웹 및 브라우저

- [ ] CSP, HSTS(HTTPS 프로필), nosniff, frame deny, referrer policy가 유지된다. (SECURITY-04)
- [ ] 외부 CDN 스크립트 또는 동적 코드 실행을 추가하지 않는다.
- [ ] `dangerouslySetInnerHTML`, `eval`, `new Function`을 사용하지 않는다.
- [ ] 프론트 저장소에 비밀값이나 신뢰할 수 없는 영구 권한 데이터를 저장하지 않는다.

## E. 예외 및 관측

- [ ] DB·파일·네트워크 경계에 명시적 오류 처리와 정리 경로가 있다. (SECURITY-15)
- [ ] 전역 예외 처리기가 안전한 상태 코드와 request ID를 반환한다.
- [ ] 구조화 로그는 timestamp, level, request ID, message를 포함한다. (SECURITY-03)
- [ ] 보안 관련 거부와 검증 실패를 공격자가 활용할 상세 없이 기록한다.

## F. 공급망 및 구성

- [ ] 새 의존성은 공식 레지스트리, 유지보수 상태, 라이선스와 필요성을 검토했다.
- [ ] npm lockfile과 Maven 버전/BOM이 정확한 버전을 결정한다. (SECURITY-10)
- [ ] `npm audit`와 OWASP Dependency-Check 결과에 차단 취약점이 없다.
- [ ] 사용하지 않는 의존성, 샘플 엔드포인트, H2 콘솔이 활성화되어 있지 않다. (SECURITY-09)
- [ ] SBOM 생성과 CI 도구 버전 고정이 유지된다.

## G. 테스트 증거

- [ ] 정상 경로뿐 아니라 잘못된 형식, 경계값, 과대 입력과 충돌을 테스트한다.
- [ ] 보안 헤더, CORS, rate limit, 안전한 오류 응답을 자동 테스트한다.
- [ ] 회귀 위험이 있는 변경에는 실패를 재현하는 테스트를 먼저 추가했다.
- [ ] 테스트 데이터와 스냅샷에 비밀값이나 실제 개인정보가 없다.

## 판정

- **PASS**: 모든 적용 가능 항목이 충족되고 N/A 항목에 근거가 있다.
- **BLOCKED**: 적용 가능한 항목이 하나라도 미충족이다. 수정 후 전체 체크리스트를 재실행한다.
